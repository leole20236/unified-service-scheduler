USER ROLES, USE CASES AND UI · UI IS MOCKUPS ONLY

Two roles, one shared schedule

Customer  B2C · web or app, 24/7

★ Book a service

tap a time ⇒ POST /me/holds · confirm ⇒ POST /me/appointments

Also: reschedule or cancel · my appointments · my vehicles

Dispatcher  B2B · workshop Gantt board

★ Run the day

board ⇒ GET /schedule · drag ⇒ PATCH + If-Match

Also: walk-ins · check in ⇒ start ⇒ complete · block a bay

UI designed, not built · ★ main use cases · the next slides follow a customer booking · 3

(~25s) The system has two kinds of users. Customers book online: they pick a car and services, choose a free time, and confirm. In the app, tapping a time holds it, and confirming books it. Dispatchers run the workshop day on a board of bays and technicians; dragging a booking sends an update. I didn't build these screens. They're mockups to show how the UI uses the API. The main use case is a customer booking a service, and the next slides follow it.
